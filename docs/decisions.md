- 2026-10-01 | 이번 구현은 Claude Code 클라우드 세션(Linux 컨테이너)에서 진행했고, 단계 0의 "MySQL 준비 후 멈춤"과 단계 8의 "실제 모델 확인 후 멈춤"에서 멈추지 않고 끝까지 진행했다. 사용자가 할 일은 docs/progress.md의 "사용자가 직접 할 일"에 모았다. | 클라우드 세션에서는 사용자가 터미널에서 바로 답할 수 없어, 멈추면 이후 단계가 모두 막히기 때문이다.
- 2026-10-01 | 컨테이너에 MySQL 8.0.46을 설치해 CLAUDE.md 명령어대로 content_ai DB를 만들고, 테스트용 content_ai_test DB를 따로 만들어 TEST_DATABASE_URL로 DB 테스트를 돌렸다. | 설계서의 DB 동작(JSON 컬럼, CHECK 제약, ENUM)을 실제 MySQL에서 확인해야 사용자 PC에서도 그대로 돌기 때문이다.
- 2026-10-01 | 코드 주석을 촘촘히 단다. 함수마다 하는 일과 입출력, 값을 정한 근거, 분기마다 판단 이유를 적는다. | 사용자가 코드를 읽으며 검토하겠다고 요청했기 때문이다.
- 2026-10-01 | 설계서 6절 표에 GET /api/projects/{id}/sources/latest와 GET /api/projects/{id}/settings를 더했다. | 자료 입력 화면과 조건 설정 화면을 다시 열 때 이전 값을 채워 넣어야 하기 때문이다.
- 2026-10-01 | PUT /api/sources/{id}/paragraphs는 그 원고를 쓴 생성 실행이 이미 있으면 원래 행을 고치지 않고 새 원고 행을 만든다. | 번호를 다시 매기면 이전 실행 장면의 근거 문단 번호가 다른 글을 가리키게 되어 근거 추적이 깨지기 때문이다.
- 2026-10-01 | 생성 조건(PUT settings)은 매번 새 행으로 저장한다. | generation_run.setting_id가 실행 당시의 조건을 가리켜야 실행끼리 비교할 수 있기 때문이다.
- 2026-10-01 | 원고 파일 크기 상한을 20MB로 두었다. | 텍스트 위주 교안으로는 충분하고, 실수로 큰 파일을 올렸을 때 서버 메모리를 지키기 위해서다.
- 2026-10-01 | llm_client.py 맨 위에 `import app.config` 한 줄을 더했다. 함수와 상수 인터페이스는 그대로다. | llm_client가 import될 때 os.getenv로 값을 읽으므로, 그보다 먼저 저장소 루트의 .env가 읽혀야 하기 때문이다.
